B) the meting_vers freshness expression, rendered by HA itself via POST /api/template
   {{ state_attr('sensor.kantoor_temperatuur', 'time') }}                                                   -> 2026-09-07T04:44:07.962Z
   {{ (as_timestamp(now()) - as_timestamp(state_attr('sensor.kantoor_temperatuur', 'time'), 0)) | round(1) }} -> 2124.5
   {{ (as_timestamp(now()) - as_timestamp(state_attr('sensor.kantoor_temperatuur', 'time'), 0)) < 1800 }}   -> False
   {{ (as_timestamp(now()) - as_timestamp(state_attr('sensor.kantoor_temperatuur', 'missing_attr'), 0)) < 1800 }} -> False
   {{ (as_timestamp(now()) - as_timestamp(state_attr('sensor.does_not_exist', 'time'), 0)) < 1800 }}        -> False

   => FAIL-CLOSED confirmed: a missing attribute or a missing entity both yield False,
      so the unit does not start. This is why continue_on_error: true on the refresh is safe.
