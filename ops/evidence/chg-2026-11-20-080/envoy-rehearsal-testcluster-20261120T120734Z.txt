Findings that change the prod procedure:
F1 G2 as written cannot work: the cluster-apps patch sets upgrade.crds CreateReplace on every HelmRelease
   (live 70/70; loki and kube-prometheus-stack set Skip in Git and still run CreateReplace). A
   "previous chart + crds: Skip" commit would be overridden. A plain revert at a CRD hop FAILS at the CRD
   apply (below, 11:45Z): backendtlspolicies v1 cannot be removed, the 1.6.7 controller stays.
   Substitute (keeps G2's intent: controller only, CRDs untouched, never a plain revert, proven here):
   flux suspend hr + helm rollback <previous chart revision> --force-conflicts --wait. Fix-forward = flux resume.
F2 helm rollback without --force-conflicts FAILS (Helm 4 server-side apply conflicts with field manager
   helm-controller); with it, it succeeds (hop 3, 5, 6 below).
F3 From 1.6 a SecurityPolicy whose extAuth Service has no ready endpoints is Accepted=False ("no ready
   endpoints") and the route answers 500 instead of 403: still fail-closed. Applies to the prod canary from
   hop 3 and to teamregie if authelia ever has 0 ready pods.
F4 Cosmetic: controller image tag is v1.10.0 while the OCI tag is 1.10.0 (hop 7 "FAIL" below is only that
   string compare; all functional checks passed).
