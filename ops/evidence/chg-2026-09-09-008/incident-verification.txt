  WHY THE ATTRIBUTION CORRECTION SHARPENS D4 RATHER THAN WEAKENING IT:
    The off-command came from an API client holding the user's LLAT, so in the logbook it is
    INDISTINGUISHABLE from the user pressing the button in the UI — identical user_id. That
    is direct evidence for the design decision taken here: the ownership inversion
    deliberately does NOT discriminate on HA context or user_id. It cannot, in either
    direction —
        a Hue wall switch or the Hue app produces NO HA context at all, and
        an agent's API call produces the USER'S context.
    So context-based ownership would have been wrong twice over. Instead the controller
    marks its own commands (sets the flag immediately BEFORE its own light.turn_on, clears
    it immediately BEFORE its own light.turn_off) and anything else is by definition
    external. That test is actor-agnostic and survives both failure modes above.

    It also means D4 is not merely a theory about what a human might do: an off-command
    from ANY source — user, Atlas, Node-RED, the Einde Werkdag automation — was being
    reverted while the room read occupied.
